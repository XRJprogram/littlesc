## 二、根因清单（坏在哪 / 怎么改 / 修前修后）

### 根因 1：空 else 分支被降级（control_if_else -28 / control_if +19）
- **坏在哪**：codegen `_genBranch` 用 `else_body.length > 0` 判断是否生成 `control_if_else`。原版 424 个 if_else 中有 26 个 SUBSTACK2 为空（合法形态），反编译正确输出 `} else {`（空体），重编译却降级成 `control_if`。
- **怎么改**：AST 的 `StmtBranch` 增加 `has_else` 标记（源码显式写了 `else` 即为 true，含 elif 链）；parser 两处解析点传入；codegen 判定改为 `has_else || length > 0`，空 else 生成带空 SUBSTACK2 的 `control_if_else`。
- **效果**：if_else -28→0，if +19→0。

### 根因 2：条件强制包裹 `== 0` 且语义反转（operator_equals +33）
- **坏在哪**：`_coerceCondition` 给非二元表达式条件包一层 `(expr == 0)`。注释写的是 `!= 0`，代码却用 `Eq` —— **布尔语义直接反转**（`if mouse_down()` 变成"鼠标没按下才执行"），且每次重编译凭空多 33 个 operator_equals。zhiteng 有 35 个布尔 reporter 条件（touching 17、keypressed 9、mousedown 9），减孤儿后与 +33 完全对账。
- **怎么改**：条件原样直传 Scratch 的 CONDITION 槽（该槽原生接受任意 reporter，非零即真）。
- **效果**：operator_equals +33→0；pyinterpreter 白赚 +10→0。

### 根因 3：孤儿块（散块链）被整体丢弃（约 46 项差异的最大头）
- **坏在哪**：原版有 24 条不连任何帽子块的散块链（Scratch 编辑器里的 loose stacks，共 138 块），decompiler 直接注释丢弃，重编译后全部消失（procedures_call -15、setvariableto -12、addtolist -12、forever/wait/broadcast -4/-4/-3 等皆源于此）。
- **怎么改**：新增 `orphan { ... }` 顶层语法贯通三层：decompiler 把每条散块链输出为 orphan 组；lexer/parser 解析为 `sprite.orphanChains`；codegen 把每条链生成无帽 topLevel 块链（首块 topLevel=true 带独立坐标，链内用 next 串接）。
- **效果**：zhiteng 50→11 项（本轮最大单项收益）。

### 根因 4：精灵 `visible:false` 属性被误转成 `hide;` 语句（looks_hide +6）
- **坏在哪**：`_emitSpriteFields` 把不可见精灵的属性转换成 `hide;` 语句**注入第一个帽子脚本**，重编译多出幻影 looks_hide 块（zhiteng 有 6 个隐藏精灵，其中 5 个差异计入直方图）。
- **怎么改**：改为输出顶层 `hide;` 声明（parser 本就支持顶层 hide/set_rotation_style 映射回精灵属性），删除 `_negFieldInits` 注入逻辑。
- **效果**：looks_hide +6→0。

### 根因 5：show/hide 不分对象（data_showlist/hidelist 各 -1）
- **坏在哪**：`_genShow/_genHide` 忽略语句的对象名，一律生成 looks_show/looks_hide。`show 列表名;` 被误编译成精灵显隐。
- **怎么改**：用 `scope.qualifyName` 判定对象类别，列表名 → `data_showlist/data_hidelist`（LIST 字段），否则 looks_show/hide。
- **效果**：showlist/hidelist 清零。

### 根因 6：零参数语句的 menu shadow 不生成（motion_goto_menu -3）
- **坏在哪**：menu shadow 生成逻辑位于**参数循环内**，`goto_mouse_pointer;` 这类零参数语句永远进不了循环，重编译后 TO 输入是裸字符串而非 menu 块（原版 3 个 `_mouse_` goto 全中招）。
- **怎么改**：参数循环后补一段：若 repr 带 menu 且 menu.input 不在参数名列表，按默认值生成 menu 块并接好 input。
- **效果**：motion_goto_menu 清零（goto/point_towards/glide 系列一并修复）。

### 根因 7：key_pressed 的 menu 结构错误 + 参数报告器丢失（argument_reporter -2）
- **坏在哪**（两处）：
  1. codegen `_genRepr` 对带命名参数 menu 的表达式，先按默认值生成 menu 并接好 input，随后参数循环又用裸字符串 `[10,"f"]` **覆盖** input，留下一个带错误值 "any" 的游离 menu 块。
  2. 反编译器遇到"参数报告器盖住 menu"形态（KEY_OPTION=[3, argReporter, menu]）时，把 menu 占位文本 `"number or text"` 当字面量输出，参数引用彻底丢失。
- **怎么改**：① `_genRepr` 重构 menu 处理：字面量参数→值写进 menu 块、input 指向 menu（`[1, menuId]` 规范结构）；报告器参数→盖在 menu shadow 上（`[3, exprId, menuId]`）。② decompiler 的 keypressed 分支检测被盖形态，改输出报告器表达式。
- **效果**：argument_reporter -2→0；keyoptions 全部带真实键名。

### 根因 8：SUBSTACK 锚点悬空——**灾难级结构 bug**（直方图测不出）
- **坏在哪**：codegen `_genStmts` 给每个语句分配**新 id**，但 if/repeat/forever/until 的 `SUBSTACK=[2, 锚id]` 指向一个**从未创建块的锚 id**——导致**所有 C 块的 body 全部成为不可达垃圾块**：zhiteng 重编译产物中 1402 个悬空引用，if/循环体在 Scratch 里实际是**空的**。opcode 直方图无法发现（块都在，只是断了）。
- **怎么改**：重写 `_genStmts` 锚定语义：父块已存在（帽子/proc 定义）→ 挂 next；不存在（C 块 SUBSTACK/孤儿链头）→ 首语句直接生成在锚 id 上，parent 回接宿主 C 块。5 处 C 块调用点同步更新。
- **附带修复**：表达式块 `parent=undefined` 的类型混乱 bug（字符串 parentId 被当对象取 `.id`，在 `_genExpr` 入口归一化）。
- **效果**：悬空引用 1402→0，产物从"结构损坏"变为完全合法。

### 根因 9：负数/空操作数的反编译形态破坏往返（control_if -2、operator 4 项、subtract +2）
- **坏在哪**（三个连环坑）：
  1. 负数字面量被 `_primitiveToExpr` 输出为 `(0 - N)`——依赖编译端常量折叠还原，形态不保真；
  2. **空操作数**（如 `operator_subtract(NUM1=[1,[4,""]])`）被输出为 `( - 1)` / `( + 1)`——`( + 1)` 使整段编译**静默失败**（`( - 1)` 则被一元负号折叠丢块）；
  3. decompiler 行 931 的"优化"把 `subtract(0,x)` 输出成 `(-x)`，而 `(-x)` 在表达式变换未覆盖的语句上下文中直接崩溃（UnOp.Minus 无编译实现）。
- **怎么改**（四件套）：
  1. `_primitiveToExpr`：负数直接输出 `-N`（字面量）；空/非数值输出 `0`；
  2. parser `_parseUnary`：`-数字字面量` 在解析期直接折叠为负 ExprValue（负字面量是值不是操作）；
  3. 删除 decompiler 的 `(-x)` 伪优化（Scratch 没有取负块，`(0 - x)` 才是规范形态）；
  4. codegen 给 `UnOp.Minus` 加兜底实现（lower 为 `operator_subtract(0, x)`），覆盖变换漏网的所有语句上下文。
- **效果**：zhiteng 最后 5 项清零。

### 根因 10：常量折叠/代数化简吞掉真实运算块（pyinterpreter join/multiply/subtract -2/-2/-2）
- **坏在哪**：visitor pass2 的编译期优化（`"" & x → x`、`1 * x → x`、`x - 0 → x`、`0 + x → x`、双字面量折叠）会把原版**真实存在**的运算块化简掉——用户放在项目里的 `("" & x)` 块重编译后消失。
- **怎么改**：为保真度禁用常量折叠与代数化简（代码保留、条件短路并注明原因）。
- **效果**：pyinterpreter multiply -2→-1 等改善；zhiteng 清零。

## 四、已知限制清单（不视为失败，均有明确理由）

1. **不可见游离块（pyinterpreter 42 块）**：原版含 42 个 `parent=null` 且 `topLevel=false` 且无任何块引用的**游离报告器簇**（letter_of 25、argument_reporter 13、operator_add 4）。这类块在 Scratch 编辑器中**不可见**（非 topLevel 不渲染），是编辑残留的 JSON 垃圾数据；goboscript 顶层语法无法表达"不可见的独立报告器"，且保留它们无用户可见价值。这是剩余 7 项差异中的 42 块来源。
2. **pyinterpreter 残留 7 块**（join 2、subtract 2、multiply 1、itemoflist 1、argument_reporter 1，占 23208 块的 0.03%）：疑似 menu 槽被报告器盖住等边缘形态，占比极小，本轮未继续追。
3. **多目标扁平化**：`compileSource` 是单 sprite 编译入口，测试管线把多目标源码合并编译为 Stage+Sprite1（测试仅对比 opcode 直方图，故不影响判定；变量/列表名警告即源于此，属测试框架既有设计）。
4. **造型 menu shadow 显示名**：重编译后 costumeshadow 名为默认值（纯编辑器外观，不影响块结构与语义）。
